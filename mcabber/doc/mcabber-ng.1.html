NAME

mcabber-ng - a Jabber (XMPP) console client configured in Lua

SYNOPSIS

mcabber-ng [ -h | -V | -n ] [ -f configfile ]

DESCRIPTION

mcabber-ng is a small Jabber (XMPP) console client, based on mcabber.
For now it needs a configuration file to start, so please copy the sample init.lua file to $XDG_CONFIG_HOME/mcabber-ng/init.lua (usually ~/.config/mcabber-ng/init.lua) and adapt your connection settings. The configuration file is a Lua script, see the CONFIGURATION FILE section.

You also need to have an existing Jabber account to use this software, as it cannot (un)register accounts yet.

Here are some of the features of mcabber:

  • SASL/SSL/TLS support.

  • MUC support (Multi-User Chat).

  • OMEMO, PGP, OTR support (OMEMO: end-to-end encryption of one-to-one chats)

  • Chat States support (typing notifications)

  • History logging: If enabled (see the CONFIGURATION FILE section), mcabber can save discussions to text history log files.

  • Commands completion: If possible, mcabber will try to complete your command line if you hit the Tab key.

  • Input line history: Any message or command entered is in the input line history and can be reused easily.

  • External actions: Some events (like receiving a message) can trigger an external action such as a shell script if you enable it in your configuration file. A sample events script ("eventcmd") is provided with mcabber source code, in the contrib directory.

  • Modules: mcabber can load modules (a.k.a. plugins) at runtime that extend its features.

OPTIONS

-h

Quick help usage message

-V

Displays mcabber version and compile-time definitions.

-f configfile

Use configuration file configfile. The directory of this file is used as the configuration directory.

-n

Load the configuration file, print the resulting options, aliases and key bindings, and exit. The exit status is not zero if the configuration file cannot be loaded.

WINDOWS/PANES

The mcabber(1) screen is divided into 4 regions. The roster, alias buddylist, is on the left. The chat window, or chat buffer, is on the right. The input line lies at the bottom of the screen, under a small log window.

Two status lines surround the log window. The bottom status line is the "main status line" and reflects mcabber general status. The other line is the "chat status line" and shows the status of the currently selected buddy.

To display buddies chat buffers, you will have to enter chat mode. You can enter chat mode by pressing enter (unless vi mode is enabled), and leave chat mode with the ESC key. Simply sending a message will also enable chat mode (unless vi mode is enabled).

There are several advantages to the two-mode implementation: first, it allows accurate "unread" message functionality, as described in the next section; without this, merely scrolling to a specific buddy will "read" the new messages of all buddies in-between. Second, it allows quickly hiding the conversation with a single keystroke. Third, it allows jumping between the few buddies with whom you are conversing with the /roster alternate command described in another section, without having to manually scroll back and forth.

KEYS

Text typing occurs in the input line; basic operations are supported (left arrow, right arrow, home/end keys, insert, delete, backspace…).

PageUp and PageDown keys are used to move in the roster.

Up and Down arrow keys can be used to move in the input line history; they jump to the previous/next line from the history beginning with the same string (from first column to the cursor column). When the input line has several rows, they move the cursor between the rows first.

Messages can have several lines: Alt+Enter (or Ctrl+j) inserts a line break, and Enter sends the whole message. The input line grows as needed (see the input_max_rows option).

Pasted text is not sent line by line: it is inserted in the input line, and Enter sends it as one message. Pasting is detected with the terminal "bracketed paste" mode, or, when the terminal doesn’t support it, when many keys including Enter are received at once. See the paste_mode option.

To send a message, move to the chosen buddy in the buddylist, type your message and hit enter. If the line begins with a slash, this will be interpreted as a command (see the COMMAND section below). Hit escape to leave the chat mode.

MCABBER’S ROSTER

The first listed item on the roster is [status], which keeps a log of everything that appears in the short log window below the main chat area. While the log window was designed for showing the latest few elements, the dedicated [status] buffer allows more comfortable viewing of the log, as well as scrolling it in a standard manner.

Group names are displayed above the items that are within them, and are indicated by --- to the left of the name.

For every real Jabber contact, the roster displays four pieces of information: the buddy’s name or alias, its online status, its authorization status, and whether there are unread messages from the buddy waiting for you.

The online status is one of the following:

o

online

f

free for chat

a

away

n

not available (labeled extended away in some clients)

d

do not disturb

_

offline (or invisible to you)

?

unknown, usually meaning you are not authorized to see this buddy’s status

x

a conference room in which you are not participating

C

a conference room in which you are participating

The authorization status indicates whether a buddy is authorized to receive your online status updates, and is displayed by the brackets surrounding the buddy’s online status. Square brackets, like [o], indicate that this buddy is authorized to receive your status. Curly braces, like {o}, indicate that they are not authorized to receive your status.

When there are unread messages from a buddy which you have not looked at, a hash mark (#) appears in the leftmost section of the roster for that buddy. The hash mark disappears once you view that buddy’s message buffer. When the user attention is requested (or when you receive a message containing your nickname in a MUC room), the hash mark is replaced with the attention sign, an exclamation mark (!).

Examples:

' --- Buds'

This is a group named Buds

#[o] John

John is online, can see your status, and sent you a message that you did not read yet

' \{?} Sally'

Neither you nor Sally have authorized each other to see your online status

' {a} Jane'

Jane is away, but she cannot see your online status

#[C] x@y.c

You are participating in x@y.c conference room, and there are unread messages

/omemo [info|own|on|off|default|trust|distrust|forget|fetch|cleanup] [jid] [device|fingerprint]

OMEMO end-to-end encryption of one-to-one chats (XEP-0384, version 0.3 "eu.siacs.conversations.axolotl", the one used by Conversations, Dino, Gajim and Profanity). Rooms are not supported. The keys are kept in ~/.config/mcabber-ng/omemo/.
With the default policy ("omemo_policy" option set to "auto"), messages to a contact are encrypted when the contact publishes OMEMO devices. When the device list of a contact is not known yet, it is fetched before the message is sent; if the contact turns out not to use OMEMO, the message is not sent and the next one is sent unencrypted. An encrypted message is never sent in plain text: if it cannot be encrypted, an error is displayed in the chat window.
New devices are trusted automatically (Blind Trust Before Verification), until you verify a device of the contact with "/omemo trust": then new devices of this contact must be trusted by hand. Set "omemo_trust" to "manual" to trust every device by hand.
When jid is omitted, the current buddy is used. A device is designated by its ID or by its fingerprint (at least its first 8 digits).

Show whether messages to jid are encrypted, and its devices with their trust level and fingerprint (without jid and buddy: this device)

own

Show this device, its fingerprint and the other devices of your account

on [jid]

Always encrypt messages to jid (never send them unencrypted)

off [jid]

Never encrypt messages to jid

default [jid]

Follow the "omemo_policy" option for jid

trust [jid] device|fingerprint

Mark the device as verified (compare the fingerprint with the contact first)

distrust [jid] device|fingerprint

Never encrypt for this device, and refuse its messages

forget [jid] device|fingerprint

Forget the keys and the session of the device

fetch [jid]

Fetch the device list and the keys of jid again

cleanup

Publish a device list that contains only this device (removes the old devices of your account)

/otrpolicy
/otrpolicy (default|jid) (plain|manual|opportunistic|always)

You can use the shortcut-jid "." for the currently selected contact.

(without arguments)

Prints all OTR policies to the status buffer

(default|jid) (plain|manual|opportunistic|always)

Sets either the default policy or the policy for the given jid The plain policy should never be used, because you won’t be able to receive or send any OTR encrypted messages. If you set the policy to manual, you or your chat partner have to start the OTR encryption by hand (e.g. with /otr start). The policy "opportunistic" does that itself by sending a special whitespace-sequence at the end of unencrypted messages. So the other OTR-enabled chat client knows, that you want to use OTR. bookmark [add|del] [-autojoin|+autojoin] [-|nick]

Add, remove or update a bookmark (default is add). If autojoin is set, mcabber will automatically join the MUC room when it connects to the server. To see the list of bookmarks, use /room bookmark in the status buffer.

/roster bottom|top|up|down|group_prev|group_next
/roster alternate|unread_first|unread_next
/roster search bud
/roster display|hide_offline|show_offline|toggle_offline
/roster item_lock|item_unlock|item_toggle_lock
/roster hide|show|toggle
/roster note [-|text]

The roster command manipulates the roster/buddylist.
Here are the available parameters:

bottom

Jump to the bottom of the roster

top

Jump to the top of the roster

up [n]

Move up [n lines] in the roster

down [n]

Move down [n lines] in the roster

group_prev

Jump to the previous group in the roster

group_next

Jump to the next group in the roster

alternate

Jump to alternate buddy. The "alternate" buddy is the last buddy left while being in chat mode. This command is thus especially useful after commands like "/roster unread_next" (Ctrl-q).

unread_first

Jump to the first unread message

unread_next

Jump to the next unread message

search bud

Search for a buddy with a name or jid containing "bud" (only in the displayed buddylist)

display [mask]

See or update the roster filter. The mask should contain the shortcut letters of the status you want to see ([o]nline, [f]ree_for_chat, [d]o_not_disturb, [n]ot_available, [a]way, [_]offline). For example "ofdna" to display only connected buddies.

hide_offline

Hide offline buddies (same as /roster display ofdna)

show_offline

Show offline buddies (same as /roster display ofdna_)

toggle_offline

Toggle display of offline buddies

item_lock [jid]

Lock the roster item so it remains visible regardless of its status

item_unlock [jid]

Undo the effects of item_lock

item_toggle_lock [jid]

Invert the current lock flag

hide

Hide roster (full-width chat window)

show

Show roster

toggle

Toggle roster visibility

note [-|text]

Set/update/delete an annotation. If there is no text, the current item’s annotation is displayed — if you are in the status buffer, all notes are displayed. If text is "-", the note is erased.

/say [-n|-h|--] text

Send the "text" message to the currently selected buddy. It can be useful if you want to send a message beginning with a slash, for example.
The "-n" flag turns the message to "normal" type, "-h" to "headline". "--" can be used to send chat message beginning with -n or -h.

/say_to [-n|-h] [-q] [-f file] jid text

Send the "text" message to the specified jid.
Please note that this command doesn’t set the default resource for a contact, so if you want to send several messages to a specific resource you will have to use "/say_to" for each message.
You can send a message to a specific resource of the currently selected contact by using /say_to ./resourcename message.
The "-n" flag turns the message to "normal" type, "-h" to "headline". "--" can be used to send chat messages beginning with -n or -h.
When "-q" is used, the message will be sent in the background and will not change the current active window.
A text file can be provided with the "-f" switch (in which case there’s no need to pass a text argument after the jid, of course).

/screen_refresh

Refresh the mcabber screen.

/set [option [= value]]

Display or set an option value.
Without arguments prints a list of all set options with their values

/source pattern

Run the Lua files that match the glob pattern (sorted in alphabetical order).
A file can be run again after it has been edited (e.g. "/source ~/.config/mcabber-ng/init.lua"): the event handlers and timers created by its previous run are removed first, and the Lua modules are loaded again by require(). The options, key bindings and styles it no longer sets keep their values.

/status [online|avail|free|dnd|notavail|away [-|statusmessage]]
/status message -|statusmessage

Show or set the current status.
If no status is specified, display the current status.
If a status message is specified, it will override the message* variables (these variables can be set in the configuration file).
If no relevant message* variable is set and no status message provided, the current status message is kept.
If StatusMessage is "-", the current status message is cleared.
With the "/status message" command, mcabber will update the message while preserving the status.

/status_to jid online|avail|free|dnd|notavail|away [statusmessage]
/status_to jid message statusmessage

Send the requested status to the specified Jabber user.
If the specified jid is ".", the current buddy is used.
Note: this status will be overridden by subsequent "/status" commands. If you are using the auto-away feature, the status will overridden too.
Note: The jid can include a resource (i.e. user@server/resource).

/members [show|hide|toggle]

Show or hide the members of the current room (see USER INTERFACE).

/console [show|hide|toggle|clear]

Display the XMPP console (see USER INTERFACE). clear empties it.

/bookmarks [set|del room [name=… nick=… password=… autojoin=on|off]]

Without arguments, select the [bookmarks] buffer (shown in the roster under [status], unless the roster_bookmarks option is 0), which lists the bookmarks of rooms. When the input line is empty: Up/Down (or j/k) select a bookmark, Enter joins the room, a toggles the auto-join, e puts a "/bookmarks set" command for the bookmark in the input line, n one for a new bookmark, d (twice) deletes the bookmark.
set creates or changes the bookmark of a room; only the given fields change (an empty value removes the nickname or the password). del deletes it. Values with spaces are quoted: name=My room.

/editor [cancel]

Edit the input line (the message being written) in an external editor: the editor option, or $VISUAL, or $EDITOR, or vi. When the editor is closed, the text replaces the input line, without its final line breaks; it can have several lines. If the editor fails (e.g. ":cq" in Vim), the input line is not changed.
Inside tmux, the editor is opened in another pane and mcabber-ng keeps running; the editor_tmux option chooses "split" (a pane next to mcabber-ng, the default), "window" (a new window), "popup" (a popup window) or "off" (in the terminal of mcabber-ng, as outside tmux, where the screen of mcabber-ng is suspended while the editor runs). editor_tmux_args gives other arguments to the tmux command (default "-h" for split-window, "-w 80% -h 80%" for display-popup), e.g. "-v -l 10" for a pane of 10 lines below mcabber-ng.
"/editor cancel" forgets an editor opened in tmux whose end mcabber-ng is waiting for.

/url [command]

Label the links displayed in the chat window (like the EasyMotion plugin of Vim), even when they are wrapped on several lines: type the label of a link to open it; Escape cancels. When there is only one link, it is opened directly.
The link is opened with the url_open_command option (default "xdg-open"), or with the given command. "%s" in the command is replaced by the URL, which is added as the last argument otherwise. The command is not run by a shell: to use one, pass the URL as a parameter (sh -c 'firefox "$1"' sh), never put "%s" in the shell code. The labels are made of the characters of the url_hint_chars option (default "asdfghjklqwertyuiopzxcvbnm"); they use the "link_hint" style.
Example: "/url wl-copy" copies a link to the clipboard.

/version

Display current version of mcabber.

CONFIGURATION FILE

The configuration file, $XDG_CONFIG_HOME/mcabber-ng/init.lua by default, is a Lua script (Lua 5.1 / LuaJIT). The provided sample configuration file (init.lua.example) documents all the options. The mc table (also available with require "mcabber") gives access to mcabber-ng:

mc.set { name = value, … }, mc.set(name, value)

Set options. Values can be strings, numbers or booleans (true is 1, false is 0); nil removes the option. mc.opt.name = value is equivalent, and mc.opt.name or mc.get(name) read an option (as a string).

mc.alias { name = "command line", … }, mc.alias(name, command)

Define command aliases.

mc.bind { [key] = command, … }, mc.bind(key, command)

Bind keys (see KEY NAMES) to command lines or to Lua functions. A function receives a table with the key name (key field). mc.unbind(key) removes a binding, mc.bindings() returns all of them, mc.key_name(name) returns the canonical name of a key.

mc.command(command line)

Run a mcabber command (the leading slash is optional). While the configuration file is loaded, only "safe" commands can be used (set, bind, alias, pgp, source, status, color, otrpolicy, module).

mc.color.roster(statuses, jid, color), mc.color.muc(room, mode), mc.color.mucnick(nick, color)

Coloring rules, see the /color command.

mc.module.load(name), mc.module.unload(name)

Load or unload a module.

mc.status(status [, message])

Set your status.

mc.timer(milliseconds, function [, repeat])

Call the function after the delay (repeatedly if repeat is true, until the function returns false). Returns an id for mc.cancel(id).

mc.on(event, function(ev) … end [, { priority = n }])

Run a function when an event occurs (see EVENTS below). Returns an id for mc.off(id). Handlers with a lower priority run first (default 0). A handler can return mc.DROP (or false) to drop the event when possible, or mc.STOP to stop running the other handlers.

mc.send(jid, text [, { subject = "…" }]), mc.say(text)

Send a message to a contact (or a room), or to the current buddy.

mc.buddy.current()

Information about the selected buddy: a table with the jid, name, type ("user", "room", "agent", "group", "special"), status and resource fields, or nil.

mc.input.get(), mc.input.set(text), mc.input.insert(text)

Read, replace or insert text in the input line.

mc.print(…), mc.log(…), mc.debug(…)

Print to the log window (mc.log also writes to the trace log file, mc.debug only when debugging is enabled).

mc.shell_quote(text)

Quote a string for the shell. Texts coming from the network (messages, nicknames…) must always be quoted before being passed to os.execute() or io.popen().

mc.version, mc.config_dir, mc.config_file

The mcabber-ng version, configuration directory and file.

Other Lua files can be loaded with require(): <config dir>/lua/ is in the module search path. The /lua command runs Lua code at runtime ("/lua 1+1" prints 2) and /source runs a Lua file.

EVENTS

Handlers receive a table describing the event. Times are Unix timestamps, statuses are "online", "free", "dnd", "notavail", "away", "invisible" or "offline".

message_in

A message has been received, before it is displayed and logged. Fields: jid, resource, nick (rooms), text, muc (room message), private (private message from a room participant), time, delayed, carbon, error, encrypted ("omemo", "pgp", "otr" or nil). The handlers can change text. mc.DROP drops the message.

message_received

A message has been displayed. Same fields as message_in, plus attention, highlight (your nick is in a room message), own (your message in a room), active (the window of this contact is open).

message_send

A message is about to be sent. Fields: jid, bare_jid, text, subject, muc, private. The handlers can change text and subject. mc.DROP cancels the message.

message_out

A message has been sent. Fields: jid, nick, text, muc, private, time, carbon (sent by another client), encrypted.

status

The status of a contact has changed. Fields: jid, resource, old, new, message, priority, time.

my_status

Your status has changed. Fields: old, new, message.

connect, disconnect

After the connection (when the roster has been received), before the disconnection.

unread

The number of unread buffers has changed. Fields: unread, attention, muc_unread, muc_attention.

subscription

A subscription request or answer has been received. Fields: type ("subscribe", "unsubscribe", "subscribed", "unsubscribed"), jid, message. mc.DROP ignores it.

receipt

A message delivery receipt has been received. Fields: jid, id.

url_open

A link is about to be opened (/url). Fields: url, command (the command given to /url, or nil). The handlers can change url; mc.DROP means that the handler has opened it.

ready, quit

The user interface is ready (before connecting), mcabber-ng is exiting.

hook-*

Hooks run by modules; the fields are the hook arguments (strings).

Lua code called by mcabber-ng (handlers, key bindings, timers) must finish within lua_timeout_ms milliseconds (default 2000, 0 disables the check). The LuaJIT compiler is disabled because compiled code cannot be interrupted; call jit.on() in the configuration file to enable it.

MESSAGE FORMAT

The text displayed before each message (the "head": time, direction mark, nickname…) can be changed with mc.format:

mc.format.message

A template for all messages, a table of templates per kind of message ("in", "out", "info", "error", "special" for the status window, "default"), or a Lua function (see below).

mc.format.time

The default time format (strftime(3) format), e.g. "%H:%M". By default it depends on the time_prefix option.

mc.format.indent

Indentation of the following lines of a message (number of columns). By default they are aligned with the text of the first line.

Templates contain text and fields:

{field}          value of the field
{field:10}       padded to 10 columns ({field:>10} on the right,
                 {field:^10} centered); {field:.10} truncated
{time:%H:%M}     time with a specific format
{?field}...{/}   text used only if the field is set ({!field}...{/}
                 if it is not set)
{#style}         the following text uses this style (general, msgin,
                 msgout, msghl, info, timestamp, readmark, status,
                 roster, nick for the color of the nickname...); {#}
                 returns to the color of the line
{{ and }}        braces

Fields: time, mark (the original "⇐=", "-→", "*"…), nick (sender in rooms and for actions, contact or own username otherwise), kind, and the flags me (action, "/me"), muc, private (private message in a room), delayed, receipt (waiting for a receipt), carbon, highlight, own (your message in a room), omemo, pgp, otr, encrypted, in, out, info, error, special.

The default format is:

{?delayed}{#timestamp}{/}{time}{#} {mark} {?private}PRIV#<{nick}> {/}
{?me}{#nick}*{nick}{#} {/}{?muc}{!me}{#nick}<{nick}>{#} {/}{/}

(without the line break). A Lua function receives a table with the fields (time is a number) and returns a string, a list of segments ("text" or { "text", "style" }), or nil to use the default format. Example:

mc.format.message = {
  default = "{time:%H:%M} {#nick}{nick:>10.10}{#} | ",
  info = "{time:%H:%M}            * ",
}

USER INTERFACE

Input line

The input line is below the chat window (input_position option: "chat", the default, or "bottom" for the bottom of the screen, as in the original mcabber).

Members of a room

The members of the current room are displayed next to the chat window (muc_members option: "column", the default; "overlay" to display them over the chat window, using only the needed height; "none"). muc_members_width sets the width (default 20), muc_members_left puts the column on the left. The /members command shows or hides the list. mc.format.members formats the items (fields: name, role, role_char, affil, status, icon, self).

XMPP console

/console displays the XML stream (the SASL credentials are masked). While the console is displayed, text typed in the input line is sent to the server as raw XML (commands still work).

Frames

The ui_borders option draws frames around the windows: "rounded", "single", "double", "heavy", "ascii" or "none" (default). The titles of the roster and log frames are set by ui_title_roster and ui_title_log; the chat status line is displayed in the frame above the chat window. Changes are applied by /screen_refresh (Ctrl-l).

Roster and status lines

mc.format.roster (a template, or a table of templates for "contact", "room", "group" and "special" items, or a function), mc.format.chat_status and mc.format.main_status change the roster items and the status lines (see MESSAGE FORMAT for the templates; {name:*} uses the available width and {>} aligns the rest on the right). mc.format.icons is a table of status icons (online, free, away, notavail, dnd, invisible, offline, unknown, room, room_out). 

Roster fields: name, jid, status, status_char, icon, pending (the
"#", "+", "." or attention sign), unread (count), count (members of
a folded group), type, selected, folded, msg, composing, paused,
sub_from, sub_to.
Chat status fields: name, jid, resource, type, type_name, status,
status_char, icon, msg (status message or room topic), chatstate
(active, composing, paused, inactive, gone), chatmode, locked,
unread, encryption ("omemo" when the next message will be
encrypted).
Main status fields: unread (sign), status, status_char, icon, info,
msg, jid.
Input prompt

mc.format.input_prompt is displayed before the input line (it uses at most a third of the width). Fields: name, jid, type (of the current buddy), chatmode, command (the line is a command), multiline (/msay mode). 

Style names can contain fields: {#status_$status} uses the
status_online, status_away... styles.
Themes

Themes are provided as Lua modules, for example mc.theme(require "mcabber.themes.modern"). The status line of the modern theme is made of rounded "islands" drawn with Powerline glyphs (a Nerd Font is needed); other characters can be used with mc.theme(require("mcabber.themes.modern").with { caps = { "▐", "▌" } }) or no caps with { caps = false }. Available themes: modern, classic (the original look), and the color themes of the original mcabber: colorcli, light, light2, mikael-256, oliver. A theme is a Lua table of styles, with options and format sections and an optional setup function (see STYLES AND THEMES); it can be written in <config dir>/lua/.

STYLES AND THEMES

Colors and text attributes are defined by styles:

mc.style("msgin", "fg=#c0caf5 bg=default")
mc.style("timestamp", { fg = "#565f89", italic = true })
mc.theme { general = "white", status = "black on cyan bold", ... }

A style is a string of words: a foreground color, "on" and a background color, "fg=COLOR", "bg=COLOR", and attributes (bold, dim, italic, underline, reverse, blink, standout); or a table with the fg and bg fields and boolean attributes. Colors are default, black, red, green, yellow, blue, magenta, cyan, white (optionally prefixed by "bright"), a palette number (0-255) or "#rrggbb". Colors are approximated when the terminal has less colors. 24-bit colors are used if the terminal supports them (e.g. TERM=xterm-direct); the ui_colors option ("auto", "8", "16", "256" or "truecolor") overrides the detection.

The styles of the interface are: general, msgin, msgout, msghl, info, timestamp, readmark, status (status lines), log, roster, rostersel (selected item), rosterselmsg, rosternewmsg, border, title, title_active, roster_group, roster_unread, status_online, status_free, status_away, status_notavail, status_dnd, status_invisible, status_offline, badge, nick_self, input, input_prompt, link_hint. The "background", "bgstatus" and "bgrostersel" entries are background colors; these names can also be used as colors in the styles ("bg=bgstatus"), so that the styles follow them. Any other name can be defined and used in formats ({#name}). The old color_* options still work for the first ones.

mc.theme(t) sets the styles of the table t; its optional options and format fields are passed to mc.set and mc.format.

KEY NAMES

A key combination is written with modifiers joined to the key by plus signs, like "Ctrl+Alt+Left". Modifiers are Ctrl (or C), Alt (or Meta, M) and Shift (or S); a minus sign can be used instead of the plus sign ("M-j"). Names are not case-sensitive, except single characters.

Named keys are: Enter, Tab, Backspace, Esc, Space, Up, Down, Left, Right, Home, End, PgUp, PgDn, Ins, Del, Begin, F1 to F63, WheelUp, WheelDown. Any other key is a single character, like "Alt+j", "Alt+ж", "Ctrl+=" or "Alt+-" ("Alt+Plus" for the plus sign).

Some combinations cannot be told apart by terminals: Ctrl+i is Tab, Ctrl+m is Enter, Ctrl+[ is Esc, and Shift with a letter is the uppercase letter ("Alt+Shift+j" is "Alt+J"). Combinations like Ctrl+Enter or Shift+Enter are only available with terminals that report them (CSI u / modifyOtherKeys).
