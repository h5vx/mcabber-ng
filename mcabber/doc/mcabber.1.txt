MCABBER(1)
===========
Mikael BERTHE <mcabber@lilotux.net>
v1.1.3-dev, October 2021

NAME
----
mcabber - a simple Jabber (XMPP) console client

SYNOPSIS
--------
'mcabber-ng' [ -h | -V | -n ] [ -f configfile ]

DESCRIPTION
-----------
`mcabber-ng` is a small Jabber (XMPP) console client, based on `mcabber`. +
For now it needs a configuration file to start, so please copy the sample
init.lua file to $XDG_CONFIG_HOME/mcabber-ng/init.lua (usually
~/.config/mcabber-ng/init.lua) and adapt your connection settings.  The
configuration file is a Lua script, see the CONFIGURATION FILE section.

You also need to have an existing Jabber account to use this software, as
it cannot (un)register accounts yet.

Here are some of the features of `mcabber`:

- 'SASL/SSL/TLS support'.
- 'MUC support' (Multi-User Chat).
- 'PGP, OTR support'
- 'Chat States' support (typing notifications)
- 'History logging:'  If enabled (see the CONFIGURATION FILE section),
  `mcabber` can save discussions to text history log files.
- 'Commands completion:'  If possible, `mcabber` will try to complete your
  command line if you hit the Tab key.
- 'Input line history:'  Any message or command entered is in the input line
  history and can be reused easily.
- 'External actions:'  Some events (like receiving a message) can trigger an
  external action such as a shell script if you enable it in your
  configuration file.  A sample events script ("eventcmd") is provided with
  `mcabber` source code, in the contrib directory.
- 'Modules:'  `mcabber` can load modules (a.k.a. plugins) at runtime that
  extend its features.

OPTIONS
-------
-h::
        Quick help usage message

-V::
        Displays `mcabber` version and compile-time definitions.

-f configfile::
        Use configuration file 'configfile'.  The directory of this file is
        used as the configuration directory.

-n::
        Load the configuration file, print the resulting options, aliases and
        key bindings, and exit.  The exit status is not zero if the
        configuration file cannot be loaded.

WINDOWS/PANES
-------------
The `mcabber(1)` screen is divided into 4 regions.
The 'roster', alias 'buddylist', is on the left.  The 'chat window', or chat
buffer, is on the right.  The 'input line' lies at the bottom of the screen,
under a small 'log window'.

Two status lines surround the log window.  The bottom status line is the
"main status line" and reflects mcabber general status.  The other line
is the "chat status line" and shows the status of the currently selected
buddy.

To display buddies chat buffers, you will have to enter 'chat mode'.
You can enter chat mode by pressing enter (unless 'vi mode' is enabled), and
leave chat mode with the ESC key.  Simply sending a message will also enable
chat mode (unless 'vi mode' is enabled).

There are several advantages to the two-mode implementation: first, it allows
accurate "unread" message functionality, as described in the next section;
without this, merely scrolling to a specific buddy will "read" the new
messages of all buddies in-between.  Second, it allows quickly hiding the
conversation with a single keystroke.  Third, it allows jumping between
the few buddies with whom you are conversing with the '/roster alternate'
command described in another section, without having to manually scroll
back and forth.

KEYS
----
Text typing occurs in the 'input line'; basic operations are supported
(left arrow, right arrow, home/end keys, insert, delete, backspace...).

PageUp and PageDown keys are used to move in the roster.

Up and Down arrow keys can be used to move in the input line history; they
jump to the previous/next line from the history beginning with the same string
(from first column to the cursor column).  When the input line has several
rows, they move the cursor between the rows first.

Messages can have several lines: Alt+Enter (or Ctrl+j) inserts a line break,
and Enter sends the whole message.  The input line grows as needed (see the
'input_max_rows' option).

Pasted text is not sent line by line: it is inserted in the input line, and
Enter sends it as one message.  Pasting is detected with the terminal
"bracketed paste" mode, or, when the terminal doesn't support it, when many
keys including Enter are received at once.  See the 'paste_mode' option.

To send a message, move to the chosen buddy in the buddylist, type your
message and hit enter.  If the line begins with a slash, this will be
interpreted as a command (see the COMMAND section below).  Hit escape to
leave the chat mode.

Here is a quick description of the default key bindings:

Esc::           Disable chat mode
Enter::         Send the message (or run the command)
Alt+Enter, Ctrl-j:: Insert a line break
Ctrl-a, Home::  Go to the beginning of the current line
Ctrl-e, End::   Go to the end of the current line
Ctrl-Home/Ctrl-End:: Go to the beginning/end of the input buffer
Ctrl-l::        Force a refresh
Up/Down::       Move between the rows of the input line, or in the input line history
PgUp/PgDown::   Move inside the roster (buddylist)
Tab::           Complete current word, in the input line
Ctrl-g::        Cancel completion
Ctrl-c::        Abort multi-line messages and completions
Ctrl-d::        Send/terminate a multi-line message
Ctrl-p/Ctrl-n:: Scroll up/down half a screen in the buffer window (chat mode)
Ctrl-Left::     Move the cursor back to the start of the current or previous word
Ctrl-Right::    Move the cursor forward to the end of the current or next word
Ctrl-u::        Delete from beginning of the line to the cursor (or join the line with the previous one)
Ctrl-k::        Delete from the cursor to the end of line (or join the line with the next one)
Ctrl-w::        Backward kill word
Ctrl-t::        Transpose chars
Ctrl-o::        Accept line and put the next history line in the input line (accept-line-and-down-history)

Additional key bindings may be specified using the '/bind' command described
in the COMMANDS section.

VI MODE
-------
If the "vi_mode" option is set to 1, `mcabber(1)` accepts a few commands
loosely based on those available in `vi(1)`'s normal mode.  In this case, chat
mode is not entered by pressing enter, and messages cannot be composed outside
of the chat mode.  The following commands are accepted:

A::             Call "/roster unread_first".
a::             Call "/roster unread_next".
F::             Call "/roster group_prev".
f::             Call "/roster group_next".
G::             Call "/roster bottom".
gg::            Call "/roster top".
i::             Enter chat mode.
[N]j::          Call "/roster down [N]".
[N]k::          Call "/roster up [N]".
n::             Repeat the previous search (if any).
O::             Call "/roster unread_first" and open chat window.
o::             Call "/roster unread_next" and open chat window.
ZZ::            Call "/quit".
zM::            Call "/group fold" for all groups.
zR::            Call "/group unfold" for all groups.
''::           Call "/roster alternate".
!::             Toggle attention flag for current buddy.
#::             Toggle unread messages flag for current buddy.
<Space>::       Call "/group toggle" for the current group.

A leading slash enables search mode:

/string::     Call "/roster search string".

A leading colon enabled command-line mode:

:q::            Call "/quit".
:N::            Jump to line N in the roster.
:CMD-LINE::     Call "/CMD-LINE" (unless the CMD-LINE matches one of the
                above commands).

Commands entered with a leading colon and searches are either submitted by
pressing enter or aborted by hitting escape.  In either case, `mcabber(1)`
returns to the normal (non-chat) mode.  History editing is supported in
command-line mode and in search mode.  In command-line mode, tab completion is
supported as well.

MCABBER'S ROSTER
----------------
The first listed item on the roster is '[status]', which keeps a log of
everything that appears in the short log window below the main chat area.
While the log window was designed for showing the latest few elements, the
dedicated '[status]' buffer allows more comfortable viewing of the log, as
well as scrolling it in a standard manner.

Group names are displayed above the items that are within them, and are
indicated by '---' to the left of the name.

For every real Jabber contact, the roster displays four pieces of information:
the buddy's name or alias, its online status, its authorization status, and
whether there are unread messages from the buddy waiting for you.

The online status is one of the following:

        'o';;  online
        'f';;  free for chat
        'a';;  away
        'n';;  not available (labeled 'extended away' in some clients)
        'd';;  do not disturb
        '_';;  offline (or invisible to you)
        '?';;  unknown, usually meaning you are not authorized to see this buddy's status
        'x';;  a conference room in which you are not participating
        'C';;  a conference room in which you are participating

The authorization status indicates whether a buddy is authorized to receive
your online status updates, and is displayed by the brackets surrounding the
buddy's online status.  Square brackets, like '[o]', indicate that this
buddy is authorized to receive your status.  Curly braces, like '\{o\}',
indicate that they are not authorized to receive your status.

When there are unread messages from a buddy which you have not looked at,
a hash mark ('#') appears in the leftmost section of the roster for that
buddy.  The hash mark disappears once you view that buddy's message
buffer.
When the user attention is requested (or when you receive a message containing
your nickname in a MUC room), the hash mark is replaced with the 'attention
sign', an exclamation mark ('!').

Examples:

        ' --- Buds';;     This is a group named 'Buds'
        '#[o] John';;     John is online, can see your status, and sent you a message that you did not read yet
        ' \{?\} Sally';;  Neither you nor Sally have authorized each other to see your online status
        ' \{a\} Jane';;   Jane is away, but she cannot see your online status
        '#[C] \x@y.c';;   You are participating in \x@y.c conference room, and there are unread messages

/add [jid [nickname]]::
        Add the "jid" Jabber user to our roster (default group), and send a notification request to this buddy.  If no nickname is specified, the jid is used.  If no jid (or an empty string "") is provided or if jid is ".", the current buddy is used.

        Example: "/add somebody@jabber.server.com Somebody"

CONFIGURATION FILE
------------------
The configuration file, $XDG_CONFIG_HOME/mcabber-ng/init.lua by default, is a
Lua script (Lua 5.1 / LuaJIT).  The provided sample configuration file
(init.lua.example) documents all the options.  The `mc` table (also available
with require "mcabber") gives access to mcabber-ng:

mc.set { name = value, ... }, mc.set(name, value)::
        Set options.  Values can be strings, numbers or booleans (true is 1,
        false is 0); nil removes the option.  mc.opt.name = value is
        equivalent, and mc.opt.name or mc.get(name) read an option (as a
        string).

mc.alias { name = "command line", ... }, mc.alias(name, command)::
        Define command aliases.

mc.bind { [key] = command, ... }, mc.bind(key, command)::
        Bind keys (see KEY NAMES) to command lines or to Lua functions.  A
        function receives a table with the key name ('key' field).
        mc.unbind(key) removes a binding, mc.bindings() returns all of them,
        mc.key_name(name) returns the canonical name of a key.

mc.command(command line)::
        Run a mcabber command (the leading slash is optional).  While the
        configuration file is loaded, only "safe" commands can be used (set,
        bind, alias, pgp, source, status, color, otrpolicy, module).

mc.color.roster(statuses, jid, color), mc.color.muc(room, mode), mc.color.mucnick(nick, color)::
        Coloring rules, see the /color command.

mc.module.load(name), mc.module.unload(name)::
        Load or unload a module.

mc.status(status [, message])::
        Set your status.

mc.timer(milliseconds, function [, repeat])::
        Call the function after the delay (repeatedly if 'repeat' is true,
        until the function returns false).  Returns an id for mc.cancel(id).

mc.on(event, function(ev) ... end [, { priority = n }])::
        Run a function when an event occurs (see EVENTS below).  Returns an
        id for mc.off(id).  Handlers with a lower priority run first (default
        0).  A handler can return mc.DROP (or false) to drop the event when
        possible, or mc.STOP to stop running the other handlers.

mc.send(jid, text [, { subject = "..." }]), mc.say(text)::
        Send a message to a contact (or a room), or to the current buddy.

mc.buddy.current()::
        Information about the selected buddy: a table with the 'jid',
        'name', 'type' ("user", "room", "agent", "group", "special"),
        'status' and 'resource' fields, or nil.

mc.input.get(), mc.input.set(text), mc.input.insert(text)::
        Read, replace or insert text in the input line.

mc.print(...), mc.log(...), mc.debug(...)::
        Print to the log window (mc.log also writes to the trace log file,
        mc.debug only when debugging is enabled).

mc.shell_quote(text)::
        Quote a string for the shell.  Texts coming from the network
        (messages, nicknames...) must always be quoted before being passed to
        os.execute() or io.popen().

mc.version, mc.config_dir, mc.config_file::
        The mcabber-ng version, configuration directory and file.

Other Lua files can be loaded with require(): <config dir>/lua/ is in the
module search path.  The '/lua' command runs Lua code at runtime ("/lua 1+1"
prints 2) and '/source' runs a Lua file.

EVENTS
------
Handlers receive a table describing the event.  Times are Unix timestamps,
statuses are "online", "free", "dnd", "notavail", "away", "invisible" or
"offline".

message_in::
        A message has been received, before it is displayed and logged.
        Fields: jid, resource, nick (rooms), text, muc (room message),
        private (private message from a room participant), time, delayed,
        carbon, error, encrypted ("pgp", "otr" or nil).  The handlers can
        change 'text'.  mc.DROP drops the message.

message_received::
        A message has been displayed.  Same fields as message_in, plus
        attention, highlight (your nick is in a room message), own (your
        message in a room), active (the window of this contact is open).

message_send::
        A message is about to be sent.  Fields: jid, bare_jid, text,
        subject, muc, private.  The handlers can change 'text' and
        'subject'.  mc.DROP cancels the message.

message_out::
        A message has been sent.  Fields: jid, nick, text, muc, private,
        time, carbon (sent by another client), encrypted.

status::
        The status of a contact has changed.  Fields: jid, resource, old,
        new, message, priority, time.

my_status::
        Your status has changed.  Fields: old, new, message.

connect, disconnect::
        After the connection (when the roster has been received), before
        the disconnection.

unread::
        The number of unread buffers has changed.  Fields: unread,
        attention, muc_unread, muc_attention.

subscription::
        A subscription request or answer has been received.  Fields: type
        ("subscribe", "unsubscribe", "subscribed", "unsubscribed"), jid,
        message.  mc.DROP ignores it.

receipt::
        A message delivery receipt has been received.  Fields: jid, id.

ready, quit::
        The user interface is ready (before connecting), mcabber-ng is
        exiting.

hook-*::
        Hooks run by modules; the fields are the hook arguments (strings).

Lua code called by mcabber-ng (handlers, key bindings, timers) must finish
within 'lua_timeout_ms' milliseconds (default 2000, 0 disables the check).
The LuaJIT compiler is disabled because compiled code cannot be interrupted;
call jit.on() in the configuration file to enable it.

MESSAGE FORMAT
--------------
The text displayed before each message (the "head": time, direction mark,
nickname...) can be changed with mc.format:

mc.format.message::
        A template for all messages, a table of templates per kind of
        message ("in", "out", "info", "error", "special" for the status
        window, "default"), or a Lua function (see below).

mc.format.time::
        The default time format (strftime(3) format), e.g. "%H:%M".  By
        default it depends on the 'time_prefix' option.

mc.format.indent::
        Indentation of the following lines of a message (number of
        columns).  By default they are aligned with the text of the first
        line.

Templates contain text and fields:

    {field}          value of the field
    {field:10}       padded to 10 columns ({field:>10} on the right,
                     {field:^10} centered); {field:.10} truncated
    {time:%H:%M}     time with a specific format
    {?field}...{/}   text used only if the field is set ({!field}...{/}
                     if it is not set)
    {#style}         the following text uses this style (general, msgin,
                     msgout, msghl, info, timestamp, readmark, status,
                     roster, nick for the color of the nickname...); {#}
                     returns to the color of the line
    {{ and }}        braces

Fields: time, mark (the original "<==", "-->", "***"...), nick (sender in
rooms and for actions, contact or own username otherwise), kind, and the
flags me (action, "/me"), muc, private (private message in a room),
delayed, receipt (waiting for a receipt), carbon, highlight, own (your
message in a room), pgp, otr, encrypted, in, out, info, error, special.

The default format is:

    {?delayed}{#timestamp}{/}{time}{#} {mark} {?private}PRIV#<{nick}> {/}
    {?me}{#nick}*{nick}{#} {/}{?muc}{!me}{#nick}<{nick}>{#} {/}{/}

(without the line break).  A Lua function receives a table with the fields
(time is a number) and returns a string, a list of segments ("text" or
{ "text", "style" }), or nil to use the default format.  Example:

    mc.format.message = {
      default = "{time:%H:%M} {#nick}{nick:>10.10}{#} | ",
      info = "{time:%H:%M}            * ",
    }

STYLES AND THEMES
-----------------
Colors and text attributes are defined by styles:

    mc.style("msgin", "fg=#c0caf5 bg=default")
    mc.style("timestamp", { fg = "#565f89", italic = true })
    mc.theme { general = "white", status = "black on cyan bold", ... }

A style is a string of words: a foreground color, "on" and a background
color, "fg=COLOR", "bg=COLOR", and attributes (bold, dim, italic,
underline, reverse, blink, standout); or a table with the 'fg' and 'bg'
fields and boolean attributes.  Colors are default, black, red, green,
yellow, blue, magenta, cyan, white (optionally prefixed by "bright"), a
palette number (0-255) or "#rrggbb".  Colors are approximated when the
terminal has less colors.  24-bit colors are used if the terminal supports
them (e.g. TERM=xterm-direct); the 'ui_colors' option ("auto", "8", "16",
"256" or "truecolor") overrides the detection.

The styles of the interface are: general, msgin, msgout, msghl, info,
timestamp, readmark, status (status lines), log, roster, rostersel
(selected item), rosterselmsg, rosternewmsg, border, title, title_active,
roster_group, roster_unread, status_online, status_free, status_away,
status_notavail, status_dnd, status_invisible, status_offline, badge,
nick_self, input, input_prompt.  The "background", "bgstatus" and
"bgrostersel" entries are background colors.  Any other name can be
defined and used in formats ({#name}).  The old color_* options still
work for the first ones.

mc.theme(t) sets the styles of the table t; its optional 'options' and
'format' fields are passed to mc.set and mc.format.

KEY NAMES
---------
A key combination is written "Modifier+...+Key".  Modifiers are 'Ctrl' (or
'C'), 'Alt' (or 'Meta', 'M') and 'Shift' (or 'S'); '-' can be used instead of
'+'.  Names are not case-sensitive, except single characters.

Named keys are: Enter, Tab, Backspace, Esc, Space, Up, Down, Left, Right,
Home, End, PgUp, PgDn, Ins, Del, Begin, F1 to F63, WheelUp, WheelDown.  Any
other key is a single character, like "Alt+j", "Alt+ж", "Ctrl+=" or "Alt+-"
("Alt+Plus" for the plus sign).

Some combinations cannot be told apart by terminals: Ctrl+i is Tab, Ctrl+m
is Enter, Ctrl+[ is Esc, and Shift with a letter is the uppercase letter
("Alt+Shift+j" is "Alt+J").  Combinations like Ctrl+Enter or Shift+Enter
are only available with terminals that report them (CSI u / modifyOtherKeys).
